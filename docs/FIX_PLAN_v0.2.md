# AgentCanvas v0.2 GUI検証指摘の修正計画（Codex 向け指示）

GUI 受け入れ検証（`docs/GUI_TEST_RESULTS_v0.2.md`）で見つかった 4 件を修正する。
ブランチ `feature/v0.2-collaboration` はチェックアウト済み。**この 4 件以外の変更は行わない**こと。

## 共通ルール

- 修正完了後に `pnpm typecheck && pnpm lint && pnpm test` をすべて green にする
- 最後に `pnpm package:dir` を実行し、`apps/desktop/release/win-unpacked` を修正込みで再生成する（後続の GUI 再検証はパッケージ版で行うため必須）
- git commit を試みる。サンドボックスで拒否された場合はブロッカー扱いせず、`docs/FIXES_DONE.md` に修正サマリを記録して続行する
- main へのマージ禁止。エラーを握りつぶす実装の禁止
- 既存の不変条件（IPC の Zod 検証・atomicWrite・contextIsolation 等。詳細は `docs/IMPLEMENTATION_PLAN_v0.2.md` の §0）を維持する

## F1（必須バグ）: 言語設定がアプリ再起動で消える

- 症状: 言語トグルで切り替えても、アプリを完全終了→再起動すると初期言語に戻る
- 確認済みの根本原因: パッケージ版レンダラーは `file://` オリジンで動くため、Chromium が localStorage をディスクに永続化しない。`agentcanvas.locale` キーは実際には一度も書かれていない
- 修正方針（必須）: **メインプロセス側のファイルに永続化する**。`recent-workspaces.json` と同じ流儀で、userData 配下の設定ファイル（例: `settings.json`）に `{ "locale": "ja" | "en" }` を atomicWrite で保存する
  - IPC を追加: 設定の読み取り / locale の保存（`ipc-validation.ts` で Zod 検証、preload・electron-api 経由）
  - レンダラー起動時にメインから locale を取得して i18n を初期化（取得失敗時は `navigator.language` フォールバック）。トグル時にメインへ保存
  - localStorage への依存は撤去してよい（残す場合も正とはしない）
- テスト: 設定ファイルの読み書き・不正値の正規化をユニットテストで担保（`recent-workspaces.test.ts` と同様の純関数分離で）
- 受入条件: パッケージ版で英語に切替→ウィンドウの×で終了→再起動→英語のまま

## F2（軽微）: Mermaid パネルの一部文言が言語切替に追従しない

- 症状: Mermaid インポート用タイトル入力欄の文言だけ、言語を切り替えても初期言語のまま残る
- 原因: マウント時に一度だけ初期値を計算して state に保持しているため
- 修正方針: 表示文言は毎レンダーで `t()` から導出する。入力の初期値として保持している場合は placeholder 化するか、locale 変更時に再計算する
- 受入条件: 言語トグル直後に当該文言も即座に切り替わる

## F3（軽微）: 保存・提案決定後に MCP コピーボタンが消える

- 症状: 保存や提案の採用/却下の後、サイドバーの MCP セクションのコピーボタンが消え、ワークスペースを開き直しても復活せず、アプリ再起動でのみ復活する
- 原因: スナップショット適用時に MCP セットアップ情報がクリアされ、再取得が「workspacePath 変更時のみ」になっている
- 修正方針: MCP 情報をスナップショット適用でクリアしない、またはワークスペースが開いている間は常に取得できるようにする（再取得条件の修正）
- 受入条件: 保存→ボタンが残り、クリックで正しい内容がコピーされる

## F4（軽微）: コメントの 人間/エージェント バッジに視覚的区別がない

- 症状: HUMAN / AGENT バッジが同一のグレー表示で、文字を読まないと区別できない
- 修正方針: CSS で色分けする（例: エージェント＝紫系/青系の背景チップ、人間＝既存グレー）。既存のデザイントーン（styles.css）に合わせること
- 受入条件: 一覧を一瞥して人間とエージェントの発言が区別できる

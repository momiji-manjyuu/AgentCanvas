## 項目ごとの詳細

### M1: 言語切り替えと保持 — △ 一部失敗

やったこと:
1. サイドバー下部の「言語」欄で「English」を押した。
2. 画面全体（サイドバー・右側パネルの見出し・ノード上の「1 TASKS」表記など）が一斉に英語に変わるのを確認。
3. その状態でアプリを完全に終了し、もう一度起動して言語を確認。

見たこと:
- **切り替えは正しく動作**。日本語→英語、英語→日本語ともに UI 全体が即座に切り替わった。
- **再起動後は言語が保持されず、日本語に戻ってしまった**。英語にして閉じても、次の起動時はまた日本語の最初の画面で立ち上がる。
- 念のためアプリの保存データ（localStorage）を直接調べたところ、言語設定のキー（`agentcanvas.locale`）がディスクに一切保存されていなかった。原因は、画面が `file://` という形式で読み込まれているため、ブラウザ部品（Chromium）がこの種の画面の設定をディスクに残さない仕様になっていること。つまり「保存しているつもりだが、実際には毎回消えている」状態。
- 強制終了ではなく、ウィンドウの閉じるボタンで普通に閉じた場合でも同じく保持されなかった（環境要因ではなく、アプリ側の作りの問題と判断）。

補足の軽微な不具合: 英語に切り替えても、Mermaid パネルの「インポート用タイトル入力欄」だけは日本語の初期値（「インポートした図」）のまま残る。これは、その入力欄が画面表示時の言語で一度だけ初期値を決めており、後から言語を変えても追従しないため。実害は小さい。

判定: 切り替え自体は合格だが、「再起動後も選んだ言語が保持される」という要件は満たさないため、**一部失敗**とする。

証拠: `agentcanvas-v02-m1-ja.png`（日本語）、`agentcanvas-v02-m1-en.png`（英語に切替後）、`agentcanvas-v02-m1-persist-reverted.png`（再起動後に日本語へ戻ってしまった様子）

### M2: 外部書き込みのライブ同期 — ✅ 合格

やったこと: アプリを開いたまま（未保存の編集なし）、外部プログラムで新しい提案を書き込んだ。アプリには一切触らずに画面の変化を待った。

見たこと: 約2〜3秒で、
- 「提案（PROPOSALS）」パネルに新しい提案「GUI live-sync test proposal」が出現（「アプリを開いている間に外部プロセスが追加」という説明文付き）。
- 「アクティビティ（ACTIVITY）」パネルに「PROPOSAL — Agent added proposal "GUI live-sync test proposal"」のエントリが出現。
- 画面右下に「External change loaded（外部変更を読み込みました）」の通知。

判定: 5秒以内に提案パネルとアクティビティの両方に反映され、合格。

証拠: `agentcanvas-v02-m2.png`

### M3: 提案の部分採用 — ✅ 合格

やったこと:
1. ツールバーの「サンプル提案を作成」ボタンで、操作が5つある提案「Add Redis Cache」を作成。
2. 5つの操作それぞれにチェックボックスが付いていることを確認（全てチェック済みの初期状態）。
3. 「ノート追加」と「タスク追加」の2つのチェックを外し、ノード追加＋エッジ2本の3つだけを残した。
4. 「プレビュー」を押し、図に反映される内容を確認。
5. 「採用」を押した。

見たこと:
- プレビューでは、チェックした3操作だけが図に反映（Redis Cache ノードと2本のエッジが緑色で仮表示）。差分サマリーは「+1 nodes, 3 changed, -0 deleted」。外したノート・タスクは反映されていない。
- 採用後、3操作だけが実際に適用された。
- 「最近の決定」を開くと、この提案が「PARTIALLY_ACCEPTED（部分採用）」として表示され、適用した操作番号「ops 0, 1, 2」も記録されていた。

判定: 操作ごとのチェック、チェックした分だけのプレビュー・適用、部分採用としての履歴表示、すべて確認でき合格。

証拠: `agentcanvas-v02-m3-preview.png`（部分プレビュー）、`agentcanvas-v02-m3.png`（部分採用後）

### M4: 理由付き却下 — ✅ 合格

- 「最近の決定」に「REJECTED  GUI live-sync test proposal」とともに、入力した理由文がそのまま表示されていた。

### M5: スレッド型コメント — ✅ 合格（注記あり）

やったこと:
1. ノード「Auth Service」を選択し、インスペクターのコメント欄から「Does Auth Service need rate limiting?」を追加。
2. そのコメントに「Yes, add a token-bucket limiter at the gateway.」と返信。
3. 別途、外部プログラムでエージェント名義のコメントを同じノードに追加し、人とエージェントの表示の違いを確認。
4. ルートコメントをクリックして解決（resolved）に切り替え。

見たこと:
- コメント追加・返信ともに成功。ノード上の表示が「3 COMMENTS」に増えた。
- 返信はルートコメントより**字下げ（インデント）して表示**され、スレッド構造が見て取れる（CSS 上も返信に左マージンが設定されている）。
- 人のコメントには「HUMAN」、エージェントのコメントには「AGENT」のバッジ（ラベル）が付き、**文字としては明確に区別**されている。
- ルートコメントをクリックすると状態が「OPEN」→「RESOLVED」に変わり、解決機能も動作。

注記（軽微）: 「HUMAN」と「AGENT」はラベルの文字は違うが、**色やスタイルでの見た目の区別は無い**（両方とも同じグレーの大文字表示）。「区別はできるが、視覚的なスタイル分けは未実装」という状態。

判定: 追加・返信（スレッド字下げ）・人/エージェントの区別・解決のいずれも動作し、合格。ただしバッジの見た目の色分けは無い点を注記。

証拠: `agentcanvas-v02-m5.png`（人2件＋エージェント1件のスレッド）、`agentcanvas-v02-m5-resolved.png`（ルートを解決した状態）

### M6: MCP セットアップのコピー — ✅ 合格（注記あり）

やったこと: サイドバーの MCP 欄にある2つのコピーボタンをそれぞれ押し、クリップボードの中身を確認。中に含まれるパスが実在するかを検証。

見たこと:
- 「Copy Claude Code command」を押すと、次の内容がコピーされた:
  `claude mcp add agentcanvas -- node "…\resources\mcp-server\bundle.cjs" --workspace "C:\Users\User\Documents\AgentCanvas Sample Workspace"`
- 「Copy JSON config」を押すと、同じサーバーパスとワークスペースパスを含む JSON 設定がコピーされた。
- サーバーのファイル（`…\resources\mcp-server\bundle.cjs`）と、開いているワークスペースのフォルダの両方が**実際に存在する**ことを確認（存在チェック＝True）。

注記（軽微なUX上の問題）: 図を保存したり提案を採用／却下した直後は、MCP 欄が「Open a workspace to generate MCP setup」という案内に変わり、コピーボタンが一時的に消える。これは内部的に MCP 情報がいったん空にされ、ワークスペースのパスが変わらない限り再取得されない作りのため。同じワークスペースを開き直しても復活せず、アプリを起動し直すと復活する。本検証ではアプリを起動し直してボタンを出してから確認した。

判定: 2種類のコピーが機能し、実在のサーバーパスと開いているワークスペースのパスが含まれることを確認でき合格。上記の「保存後にボタンが消える」点を注記。

証拠: `agentcanvas-v02-m6.png`

### M7: PNG／HTML エクスポート — ✅ 合格

やったこと: ツールバーの「PNG エクスポート」「HTML エクスポート」をそれぞれ押し、OS 標準の保存ダイアログで `%TEMP%`（一時フォルダ）に保存。ファイルの中身を検証。

見たこと:
- どちらもネイティブの「名前を付けて保存」ダイアログが開いた。
- 保存された PNG: サイズ 約872KB（10KB を大きく上回る）、正しい PNG ヘッダ、画像サイズ 6424×4026 の有効な画像。
- 保存された HTML: サイズ 約1.1MB。中に図の画像（base64 形式で埋め込み、単体で表示可能）と、タイトル（System Overview）、Tasks／Notes／Comments の文章セクションが含まれていた。コメント欄には M5 で追加した3件のコメントも反映されていた。外部ファイルに依存しない単体の HTML として完結している。

判定: 両エクスポートが保存ダイアログ経由で動作し、PNG は有効な大判画像、HTML は図と文章を含む単体ファイルとして成立しており合格。

証拠: `agentcanvas-v02-m7.png`（エクスポート完了の様子）、`agentcanvas-v02-m7-exported-diagram.png`（実際に書き出された PNG）

### M8: 未保存編集中の外部変更とリロード — ✅ 合格

やったこと:
1. まず「Worker」ノードを下方向にドラッグして移動（＝未保存のローカル編集を作成）。
2. その状態のまま、外部プログラムで新しい提案（新しいID）を書き込んだ。
3. ツールバーの「リロード」ボタンを押した。

見たこと:
- **（自動マージ）** リロードを押す前の段階で、ファイル監視が外部変更を検知し、自動で**安全なマージ**を実行した。新しい提案「M8 dirty-state external proposal」が提案パネルに出現し、同時に**自分のローカル編集（Worker の移動）も保持**された。通知は「External changes merged without losing 1 collaboration item（コラボ項目を1件も失わずに外部変更をマージしました）」。
- **（リロードボタン）** まだ未保存の編集が残っているため、リロードを押すと確認ダイアログ「Discard unsaved local changes and reload this diagram from disk?（未保存のローカル変更を破棄して、ディスクから読み直しますか？）」が表示された。誤って編集を失わないための安全策。
- 「OK」を選ぶと、ディスクから読み直し。Worker ノードは元の位置に戻り（未保存のドラッグは破棄＝意図どおり）、外部の提案はディスク上にあるため残った。通知は「Reloaded diagram from disk」。
- アプリは一切クラッシュしなかった。

ローカル編集の扱いのまとめ: 外部変更が来た瞬間は「マージ」でローカル編集を保ったまま外部の内容も取り込む。その後ユーザーが明示的にリロードを選ぶと、確認の上でローカル編集を破棄してディスクの内容に揃える。どちらも安全側の挙動。

判定: 外部提案が反映され、クラッシュも無く、マージ通知も確認できたため合格。

証拠: `agentcanvas-v02-m8.png`（リロード後：Worker は元位置、外部提案は残存）

## 気づいた点（UX・不具合のメモ）

1. **【要修正・M1】言語設定が再起動後に保持されない。** 画面が `file://` で読み込まれているため、選んだ言語（および将来 localStorage に保存する他の設定）がディスクに残らない。対策案: 言語設定をメインプロセス側のファイル（設定ファイル）に保存して起動時に読み込む、またはレンダラーを `file://` 以外（カスタムプロトコル等）で配信して localStorage を永続化する。
2. **【軽微・M1】** Mermaid パネルの「インポート用タイトル」入力欄だけ、言語切り替えに追従せず初期言語の文言が残る。
3. **【軽微・M6】** 保存・提案採用／却下の後に MCP のコピーボタンが消える（同じワークスペースを開き直しても復活しない）。MCP 情報を空にした後に再取得する条件が「ワークスペースのパス変更時のみ」になっているのが原因。保存後も MCP 情報を保持する、もしくは空にしたら即再取得するのが望ましい。
4. **【軽微・M5】** 人（HUMAN）とエージェント（AGENT）のコメントバッジは文字では区別されるが、色やスタイルでの視覚的な区別が無い。一目での見分けやすさのため色分けがあると良い。
